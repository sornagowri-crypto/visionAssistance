1. FIELD OF INVENTION

The present invention relates generally to computer vision, artificial intelligence, assistive technology for visually impaired persons, mobile user interface design, and human-computer interaction (HCI). More specifically, the invention relates to an accessibility-centric, hands-free mobile platform capable of capturing camera feed frames, performing hybrid edge-cloud multimodal vision analysis, delivering real-time audio and tactile feedback, enabling continuous voice command processing, and operating seamlessly across connected and offline environments.

2. BACKGROUND OF INVENTION

Visual impairment affects hundreds of millions of people worldwide. Traditional visual assistance aids range from conventional canes and guide dogs to modern digital smartphone utilities. However, conventional digital assistive tools present significant technical limitations:

  • Superficial Classification: Existing visual identification mobile applications rely on basic object detection or optical character recognition (OCR) models that produce raw, unstructured labels (e.g., "chair", "bottle", "book") without providing detailed contextual context, aesthetic descriptions, functional use, or physical safety warnings.
  • Connectivity Dependency: Most generative AI and cloud vision services fail completely when internet access is degraded or unavailable, leaving visually impaired users without aid in low-connectivity or emergency situations.
  • Complex Touch Interfaces: Standard mobile application interfaces depend heavily on precise visual layout navigation and complex touch gestures, posing high cognitive load and physical barriers for individuals with severe visual impairment or blindness.
  • Lack of Synchronized Multi-Sensory Feedback: Conventional systems lack unified, multi-sensory feedback loops that harmonize speech synthesis, distinct tactile vibration signatures, and continuous hands-free voice control.
  • Inaccessible Configuration: User profile management and emergency contact configuration in existing mobile utilities require manual keyboard input and visual form navigation, rendering initial app configuration difficult for target users.

There exists an urgent need for an intelligent, robust, hands-free assistive technology platform that addresses these shortcomings through structured multimodal scene reasoning, edge-cloud resiliency, continuous voice-driven control, and intuitive sensory feedback.

3. OBJECTIVES OF INVENTION

The primary objectives of the present invention are to:

  1. Provide Rich Multimodal Scene Perception: Utilize Generative Artificial Intelligence (Google Gemini Vision API) to extract and articulate structured object breakdowns comprising specific object names, detailed physical appearance (color, shape, artwork, cover design), practical usage descriptions, and critical physical safety cautions.
  2. Ensure Offline Operational Resiliency: Implement an automatic network connection monitoring system that seamlessly fails over to on-device edge machine learning (Google MLKit Object Detection) in offline environments.
  3. Enable Fully Hands-Free Voice Control: Provide an "Always-On" voice command listener equipped with continuous auto-restarting capabilities, supporting localized voice triggers ("Scan", "Repeat", "Stop", "History", "Share") without requiring visual touch interaction.
  4. Deliver Distinct Tactile/Haptic Signals: Incorporate a multi-pattern vibrational feedback engine that maps specific tactile pulse sequences to camera state transitions (e.g., camera ready, picture captured, analysis complete, error encountered).
  5. Facilitate Voice-Guided Profile Setup: Offer an interactive voice interview engine that verbally queries users and populates profile fields (name, emergency contacts, medical notes) using speech recognition.
  6. Provide Emergency & Direct Contact Integration: Enable one-touch or hands-free voice sharing of current visual scan results directly to configured emergency contacts via native messaging protocols.
  7. Ensure Maximum Visual Accessibility: Implement an accessibility-first visual layout boasting ultra-high contrast (vivid yellow #FFD600 on deep black #0A0A0A), oversized tap targets (minimum 112px radius), and enlarged typography.

4. SUMMARY OF INVENTION

The present invention discloses an accessible, AI-powered mobile assistive framework—termed Vision Assistant—configured to aid visually impaired individuals in perceiving and navigating their physical environment.

The system comprises:

  • A Live Camera Preview Engine operating in full-screen mode with automated lifecycle initialization;
  • A Hybrid Edge-Cloud Vision Pipeline featuring a cloud-based Large Multimodal Model (LMM) analysis module and an on-device Machine Learning (ML) edge fallback module;
  • A Structured Prompt & Parsing System that constrains generative output into distinct semantic fields (OBJECT, APPEARANCE, USE, SAFETY);
  • An Accessibility Speech Synthesis Engine with custom speech rates, pitch modulation, and spoken text formatting;
  • A Multi-Pattern Haptic Feedback Engine providing tactile state confirmation;
  • A Continuous Voice Command Module running speech recognition with automated session resuscitation;
  • A Voice Interview Module for interactive user profile creation; and
  • A Cloud Synchronization & Emergency Integration Layer using Firebase Authentication, Firestore real-time databases, Cloud Storage, and native SMS protocol handlers.

5.2 Subsystems & Technical Details

1. Live Camera Preview Engine (camera_screen.dart): Automatically initializes device camera upon launch in full-screen aspect ratio. Evaluates real-time permissions on Android/iOS devices (Permission.camera). Captures raw high-resolution frame buffers (ImageFormatGroup.jpeg) on tap or voice trigger.

2. Structured Gemini Vision Prompting & Parsing Engine (gemini_service.dart, constants.dart): When online, the high-resolution frame buffer is converted to Base64 payload and dispatched via REST HTTP POST to the Google Gemini Vision LMM endpoint. The engine employs an accessibility-calibrated system prompt:

OBJECT: [Name of the main object]
APPEARANCE: [Detailed description of colors, shape, pattern, cover design, artwork]
USE: [Primary utility in 1-2 sentences]
SAFETY: [Identified hazards or "No safety concerns"]

The response is parsed via Regular Expression matchers (RegExp(r'OBJECT:\s*(.+)')) into a strongly typed data model (GeminiResult), synthesizing natural spoken descriptions: "I can see [Object]. It [Appearance]. It is used for [Use]. Safety note: [Safety]."

3. On-Device Offline Machine Learning Fallback (mlkit_service.dart): If network connection test (Connectivity().checkConnectivity()) returns offline status, the pipeline routes the frame buffer to localized Google MLKit Object Detector (google_mlkit_object_detection), filtering classification labels with confidence scores > 0.5 and delivering audio offline announcements.

4. Continuous Voice Command Manager (voice_command_service.dart): Provides hands-free control via speech_to_text with extended listening windows (45s max, 15s pause tolerance). Integrates a self-healing auto-restart timer (300ms) triggered on speech status done or notListening to guarantee continuous background operation. Classifies triggers into: "Scan", "Repeat", "Stop", "History", and "Share".

5. Tactile Vibration Signal Engine (vibration_service.dart): Encodes system states into distinct haptic patterns (durations in milliseconds):

  • Camera Ready: [0, 80] (1 short pulse)
  • Image Captured: [0, 80, 100, 80] (2 short pulses)
  • Description Ready: [0, 400] (1 long pulse)
  • System Error: [0, 80, 50, 80, 50, 80] (3 rapid pulses)

6. Accessibility Text-to-Speech Engine (tts_service.dart): Built upon flutter_tts, configured with speech rate 0.45 (reduced speed for clarity) and pitch 1.0. Automatically selects natural Google neural speech engines (en-US).

7. Voice-Guided Interactive Profile Setup (profile_screen.dart): Features an automated voice interview assistant that sequentially queries five critical fields (Name, Age, Emergency Contact, Emergency Phone, Medical Notes) via speech synthesis and saves output to Firebase Firestore.

8. Direct Emergency Sharing Module (camera_screen.dart): Interrogates saved user profile for emergency contact phone numbers and constructs direct platform SMS URI intents (sms:PHONE?body=Scan Result) for single-tap or voice-activated immediate emergency location/object dispatch.

6. WE CLAIM

What is claimed is:

1. A system for assisting visually impaired users through real-time multimodal visual perception, comprising:
a camera capture module configured to capture image frame buffers of an surrounding physical environment;
a network connectivity module configured to evaluate network availability in real-time;
a hybrid vision processing pipeline comprising a cloud generative multimodal artificial intelligence (AI) engine and an on-device machine learning (ML) edge detection engine, wherein captured image frame buffers are dynamically routed to said cloud AI engine when online and to said on-device ML edge detection engine when offline;
an accessibility speech synthesizer configured to convert output from said hybrid vision processing pipeline into spoken audio descriptions; and
a haptic feedback module configured to output distinct vibration pulse sequences corresponding to real-time operational state transitions of the system.
2. The system of claim 1, wherein said cloud generative multimodal AI engine is configured to execute a structured system prompt that constrains visual analysis into separate semantic output components comprising an OBJECT identification component, an APPEARANCE component detailing visual pattern and physical texture, a USE component describing functional utility, and a SAFETY component identifying physical hazards.
3. The system of claim 1, wherein said hybrid vision processing pipeline automatically formats generated descriptions into a standardized spoken sentence template optimized for auditory comprehension.
4. The system of claim 1, further comprising a continuous voice command listener configured to analyze user voice input during active camera operation, match speech input against predetermined voice command triggers comprising scan, repeat, stop, history, and share, and automatically restart speech recognition listening sessions via an automated timer loop upon session timeout or closure.
5. The system of claim 1, wherein said haptic feedback module stores distinct vibrational pulse duration arrays comprising a single short pulse for camera ready state, a double short pulse for image capture state, a single long pulse for description ready state, and a triple rapid pulse for system error state.
6. The system of claim 1, further comprising a voice interview module for user profile configuration, wherein said module sequentially synthesizes spoken questions for user profile fields, listens for verbal spoken responses, parses said responses, and saves user profile data to a database without requiring manual visual touch input.
7. The system of claim 1, further comprising a direct emergency dispatch module configured to extract emergency contact details from a user profile and generate an automated Short Message Service (SMS) URI payload containing the last visual description output for immediate transmission.
8. A method for providing real-time scene description for a visually impaired user on a mobile computing device, the method comprising:
initializing a camera preview upon application launch;
receiving a user initiation trigger via a physical tap gesture or a spoken voice command;
capturing an image frame from the camera preview;
determining connectivity status of the mobile device;
routing the captured image frame to a cloud-based Generative Vision LMM when connected, or to an on-device ML object detector when disconnected;
parsing results into structured object identity, visual detail, usage, and safety categories;
generating a tactile vibration signal corresponding to completion of analysis; and
vocalizing the structured results using text-to-speech synthesis at a reduced speech rate.
9. The method of claim 8, further comprising maintaining an always-on continuous voice listening loop that automatically detects spoken keywords while ignoring ambient noise, and auto-resuscitates listening sessions upon transient network or timeout errors.
10. An accessible graphical user interface for visual assistant software, comprising:
a high-contrast dark visual color palette featuring a near-black background (#0A0A0A) and vivid yellow primary elements (#FFD600);
a full-screen camera preview display;
an oversized circular scan trigger button having a minimum target dimension of 112 density-independent pixels; and
a pulsing voice microphone visual indicator synchronized with background voice command listening states.
